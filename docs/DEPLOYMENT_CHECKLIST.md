# פריסה והתקנה — פעולות לביצוע לאחר סקירה

עדכון 28.10.2026: הגרסה נפרסה ב־Hobby עם הגנה על כל הכתובות, ונבדקה בענן. [דוח הפריסה](DEPLOYMENT_20261028.md) · [מדריך התקנה ושימוש](LIVE_APP_GUIDE.md). התקנה ובדיקת חלונות השמירה בשני מחשבי המשרד עדיין נדרשות.

## תצורה מוכנה במאגר

- Vite סטטי, buildCommand הוא `npm test && npm run build`, תיקיית פלט `dist`.
- manifest ואייקון, שם אפליקציה, כיוון עברי וחלון standalone. אין התחייבות לעבודה ללא אינטרנט.
- קבצי מקור, בדיקות, רפרנסים ותוצרי בדיקה אינם מוגשים לציבור; רק dist משמש כתוכן האתר. קובצי outputs מוחרגים גם מהעלאת CLI.
- פרטי חיבור שנבדקו: חשבון evenrom, מאגר evenrom/Bill-of-Quantities. אין צורך להכניס Token למאגר.

## לפני פריסה

1. להשלים סקירה מקומית ותיקונים, ולוודא שהשינויים הרצויים במאגר. אין לבצע push אוטומטי של תוצרי בדיקה או שינויים שאינם שייכים למוצר.
2. לאמת בתנאי Vercel ובחשבון שהתוכנית שנבחרה מתאימה לשימוש. לא להפעיל תוכנית בתשלום ללא החלטת המשתמש. [מדיניות השימוש](https://vercel.com/docs/limits/fair-use-guidelines).
3. לקשר פרויקט חדש או קיים למאגר הנכון; לבדוק owner/project לפני כל פעולה. להגדיר Vercel Authentication עבור All Deployments, כולל כתובת הייצור, ולבדוק בפועל שמשתמש לא מורשה נעצר. מנגנון זה זמין גם להגנת production לפי [עדכון Vercel מ־9.9.2026](https://vercel.com/changelog/protect-production-deployments-for-free-on-every-plan).
4. להעניק גישה לשני המשתמשים המורשים ולבחור כתובת יציבה. העלאה ראשונה לסביבת בדיקה מוגנת, בדיקת קבצים, הדפסה וחידוש הזדהות.
5. לאשר כתובת ייצור סופית, להריץ בדיקת עשן ולהכין חזרה לפריסה קודמת במקרה הצורך.

## בכל אחד משני המחשבים

1. לפתוח בכרום את כתובת הייצור ולהזדהות.
2. ללחוץ על „התקנה כאפליקציה” או על אפשרות ההתקנה בתפריט Chrome. לבדוק סמל, חלון נפרד והפעלה מחודשת.
3. ליצור פרויקט, לשמור בשם, לעדכן אותו ולפתוח מחדש. לבדוק גם ביטול חלון בחירה ושלילת הרשאת כתיבה, כשל כתיבה וקובץ ששונה מחוץ למערכת.
4. להעביר קובץ מהמחשב הראשון לשני ולוודא תוכן, לוגו, פרקים כבויים, סעיפים מוקפאים ותבנית מותאמת.
5. להפיק Excel ו־PDF ולוודא ששניהם נשמרו ונפתחים. לבדוק הרשאת חלונות קופצים ותיקיית הורדות.
6. לבדוק חזרה אחרי סגירה, הזדהות מחדש, אזהרת שינויים שלא נשמרו וטעינת גרסת אתר חדשה לאחר שמירה.

יש להחליט במשרד היכן שומרים ומגבים קבצים וכיצד מתאמים עבודה בתור על אותו קובץ. אין מנגנון נעילה מרכזי או סנכרון פרויקטים.
