# דוח בדיקת עמידות פורמט מוקדמת

תאריך: 26.10.2026. נתוני ניסוי סינתטיים בלבד. לא נעשה שימוש בתוכן הארכיון או בנתוני פרויקט מהרפרנס.

## מסקנה

**יש בסיס מעשי לפורמט `.xlsx` עם תאי עריכה כמקור אמת ונתוני מבנה בגיליונות/עמודות פנימיים.** בבדיקה הממוקדת עברו 19 מתוך 19 בדיקות בכל אחד משני המסלולים: Excel מקומי והמרה ל־Google Sheets וחזרה ל־Excel.

זו הוכחת היתכנות לשימור נתונים, לא אישור לפורמט המוצר המלא, לתאימות כל קובץ Excel או לעימוד A4. הפורמט המלא ייבדק שוב לאחר מימוש.

## מה בוצע בפועל

1. נוצר `baseline.xlsx` עם פרק פעיל, פרק כבוי מוסתר וגיליון `_BOQ_META` מוסתר. מזהי שורות וסוגי שורות נשמרו בעמודות G:H מוסתרות. הכמות, התיאור והמחיר נשמרו רק בתאי העבודה.
2. המסלול הראשון פתח את הקובץ ב־Microsoft Excel המותקן, גרסה 16.0, build 20527, באמצעות API האוטומציה של Excel. שונו B2 (תיאור עברי רב־שורות), D2 (כמות מ־2.5 ל־4), E4 (מחיר ריק ל־20); בוצע חישוב מלא ונשמר `excel-roundtrip.xlsx`.
3. המסלול השני העלה את אותו מקור דרך חיבור Google Drive והמיר אותו ל־Google Sheets מקורי. אותם שלושה תאים נערכו באמצעות Sheets API; התוצאות נקראו בחזרה. הקובץ יוצא מחדש ל־xlsx והורד כ־`google-roundtrip.xlsx`.
4. שני הקבצים השמורים נקראו מקומית ונבדקו מול המקור. הבדיקה השוותה תאי מידע, מזהים, סוגים, נראות גיליונות, נוסחאות מורחבות ותוצאות חישוב ששמרו המנועים האמיתיים.
5. נבדקו חמישה מקרי פגיעה בזיכרון על קורא הניסוי: מטא־דאטה חסר, מזהה שורה חסר, מזהה כפול, גרסת סכמה לא מוכרת ושם גיליון לא תואם. כולם זוהו והופנו למסלול ייבוא מונחה. אלו סימולציות פגיעה, לא עריכות שבוצעו באפליקציות החיצוניות.

גיליון Google שנוצר לבדיקה: [BOQ format compatibility probe](https://docs.google.com/spreadsheets/d/1ptwCwsZGRJdZ0M2iKYXDYXPylu6-MOjwdVEzgWSAz74/edit). הוא כולל נתוני ניסוי בלבד ונשאר זמין לבדיקה חוזרת.

## תוצאות

| בדיקה | Excel | Google Sheets → xlsx |
| --- | --- | --- |
| מטא־דאטה ומצב פעילות פרקים | נשמרו | נשמרו |
| תוכן הפרק הכבוי ומצב הסתרה | נשמרו | נשמרו |
| מזהי שורות, סוגי סעיף/הערה ועמודות מוסתרות | נשמרו | נשמרו |
| תיאור עברי וירידת שורה לאחר שינוי | נשמרו | נשמרו |
| שינוי כמות ומחיר בתאים | נקלטו | נקלטו |
| נוסחאות לאחר הרחבת shared formulas | זהות למקור | זהות למקור |
| 4 × 12.34 | 49.36 | 49.36 |
| 3 × 20 | 60.00 | 60.00 |
| מחיר אפס / כלול / לא רלוונטי | אפס עם הבחנה בין המצבים | אפס עם הבחנה בין המצבים |
| כמות חסרה | סכום ריק, לא אפס | סכום ריק, לא אפס |
| מחיר טקסטואלי שגוי | „קלט לא תקין” | „קלט לא תקין” |
| עיגול 0.5 × 0.01 | 0.01 | 0.01 |
| סכום חלקי לאחר השינויים | 109.37 | 109.37 |

מחיר ריק נבדק לפני השינוי: אינו אפס. ב־Sheets נקראה גם התצוגה `49.36₪`, `60.00₪` ו־`109.37₪`; הערכים נותרו מספריים. סכום הניסוי מסומן מראש „חלקי”, כיוון שיש בו שורות חסרות/שגויות במכוון. שיעור המע״מ נשמר כמטא־דאטה סינתטי; חישוב מע״מ וריכוז רב־פרקי אינם נכללים בבדיקה הזו.

## ממצאים טכניים שהשפיעו על התכנון

- אין צורך להסתמך על JSON נסתר עם עותק מיושן של התיאור והכמות. תאי גיליון רגילים ומזהים נפרדים שרדו את שני המסלולים שנבדקו.
- השוואת XML נאיבית של נוסחאות הצביעה בתחילה על הבדל. לאחר פענוח shared formulas הנוסחאות היו זהות. אין לבלבל שינוי ייצוג פנימי עם פגיעה בנוסחה.
- מנוע ההפקה המקומי הבחין בצורה לא עקבית בין אפס למחרוזת ריקה בנוסחת ניסוי ראשונה. הנוסחה שונתה לבדיקה מפורשת באמצעות ISBLANK, ואז נבדקה בשני המנועים האמיתיים. אין להסיק תאימות מחישוב בספריית ההפקה בלבד.
- אין הגנת מידע באמצעות הסתרת גיליון. ייצוא לקבלן חייב להיבנות בנפרד ללא פרקים כבויים, ולא רק להסתיר אותם.
- קורא הניסוי אינו יבואן מוצר מלא. זיהוי שינוי סמנטי בעקבות מיון חלקי או שינוי מבני חופשי לא הוכח.

## גבולות הבדיקה

הוצגו ונבדקו תצוגות טווחים של קובץ הניסוי באמצעות כלי רינדור. בדיקת הנתונים ב־Google נעשתה במנוע Google עצמו דרך API. **לא נערכה בדיקת הדפסה חזותית ב־Excel או ב־Google Sheets, ולא אושרו RTL, שוליים, לוגו, מעברי עמודים או A4.** קובץ הניסוי אינו דוגמת העיצוב המיועדת למוצר. סבב הפעלה של אתר ופעולות Save/Save As בכרום לא בוצעו, כי המוצר טרם נבנה.

הבדיקה מאשרת רק את התכולה שנבדקה בגרסאות ובמסלולים הללו, ולא שימור לאחר כל עריכה או בכל גרסת תוכנה. שינויים מבניים עמוקים מחייבים מסלול ייבוא מונחה. קובץ עם מידע שנמחק אינו ניתן לשחזור מלא ללא מקור אחר.

## קבצים ויכולת שחזור הבדיקה

כל חומרי הניסוי נמצאים ב־`outputs/format-probe-20261026/`:

- `baseline.xlsx`, `excel-roundtrip.xlsx`, `google-roundtrip.xlsx` — מקור ושני תוצרים אמיתיים.
- `verification.json` — 19 בדיקות לכל מנוע ותוצאות חמש סימולציות הפגיעה.
- `excel-result.json` — גרסת Excel ותוצאות לפני/אחרי חישוב.
- `probe.mjs`, `set_probe_metadata.py`, `native_excel.ps1`, `verify.py` — בניית הניסוי, תכונות הסתרה, סבב Excel והשוואה. קוד בדיקה בלבד, לא קוד מוצר.

השוואה חוזרת: להריץ `verify.py` באמצעות Python הכולל openpyxl לקריאה. אין צורך להתחבר ל־Google או לפתוח Excel כדי להשוות שוב את התוצרים שנשמרו. חזרה על המסלול החיצוני המלא דורשת יצירה מחדש, פתיחה ושמירה ב־Excel, ייבוא ל־Sheets, אותן שלוש עריכות וייצוא מחדש.

SHA-256 של רפרנס העימוד לפני ואחרי הבדיקה: `0acba9a7c145136698372b73189efb1f4a24f97281320df3f376213cc39422ba`. הקובץ לא השתנה. גם גוף שש התבניות נשמר ללא שינוי; עודכנו רק הוראות המוצר והמהדורה.
