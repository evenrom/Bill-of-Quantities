## שינויים הנדרשים לפריסה

1. הוקם פרויקט Vite סטטי, Node.js 24.x, התקנה `npm ci`, בנייה `npm test && npm run build`, פלט `dist`.
2. `.vercelignore` מחריג תוצרי עבודה, רפרנסים, קובצי סביבה ומסמכים שאינם דרושים לבנייה. אפיון התבניות נכלל בבנייה משום שבדיקות התוכן קוראות אותו, אך אינו מוגש באתר.
3. קישור ה־manifest ב־HTML הוגדר עם `crossorigin="use-credentials"`. זה נדרש לטעינת פרטי ההתקנה כשהאתר מוגן בכניסה, גם באותו מקור: [תיעוד MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest).
4. נוספו `playwright.deployment.config.ts` ו־`scripts/check-deployment.mjs` לבדיקת גרסה חיה. פרטי בדיקת ההזדהות נקראים מקובץ עוגיות זמני מחוץ למאגר; אין סודות בקוד או בתוצרים.
5. בדיקת איסור פניות חיצוניות הותאמה למקור הנוכחי של האתר, כדי שתעבוד גם בענן ולא רק בכתובת localhost.

## עדכון וחזרה לגרסה קודמת

הספרייה קושרה מקומית לפרויקט המדויק; `.vercel` ו־`.env.local` מוחרגים מ־Git ומהפריסה. יש לאמת את בעל הפרויקט לפני עדכון:

```powershell
vercel project inspect --non-interactive
npm test
npm run build
npx playwright test
vercel deploy --prod --skip-domain --project bill-of-quantities --scope rom-s-projects1
```

יש לבדוק את הפריסה החדשה לפני `vercel promote <deployment-url> --scope rom-s-projects1`. את הבדיקות המאומתות אפשר להריץ עם קובץ עוגיות זמני שנוצר באמצעות `vercel curl`; אין להכניס עוגיות או סודות למאגר.

לאחר שיש גרסת ייצור קודמת תקינה, אפשר לחזור אליה באמצעות `vercel rollback --scope rom-s-projects1`. ב־Hobby החזרה מוגבלת לגרסת הייצור הקודמת. הפריסה הנוכחית היא גרסת הפתיחה שנבדקה; המועמד הראשון, לפני תיקון manifest, אינו מומלץ לשחזור.
